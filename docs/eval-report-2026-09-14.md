> 环境：deepseek-flash（评测中途账户余额耗尽，见「阻塞项」）

## 一、结论摘要

| # | 结论 | 证据强度 |
|---|---|---|
| 1 | **规划类通道（分解/退步/HyDE）引入不可复现性** | 强：同配置两次运行结果不同 |

## 三、实验二：确定性配置双轮（无 LLM 参与）

规划类特性不开时，全流程无 LLM 调用，可完全复现：

| 配置 | hit@5 (R1/R2) | MRR (R1/R2) | 两轮一致 |
|---|---|---|---|
| none(纯向量) | 0.625 / 0.625 | 0.4000 / 0.4000 | 是 |
| routing+keywords | 0.750 / 0.750 | 0.5104 / 0.5104 | 是 |
| routing+keywords+**rewrite** | 0.750 / 0.750 | **0.5042 / 0.5042** | 是 |
| routing+keywords+rewrite+graph | 0.750 / 0.750 | 0.5250 / 0.5250 | 是 |

- **两轮完全一致** → 确定性配置可复现；方差只可能来自 LLM 通道。
- **加改写后 MRR 0.5104 → 0.5042（−0.006）**，hit@5 不变 → 改写无正向贡献。

## 四、发现一：规划通道破坏可复现性

同一条查询（#5「什么是 FastAPI？它有什么特点？」）在同一配置下：

- 首轮消融的 `default(含改写)`：**未命中**
- 手工单跑同一配置：**命中**
- 首轮消融的 `none(纯向量)`：**命中**

唯一差异是规划类特性（decompose / stepback / hyde）会调 LLM 生成子查询、退步问题、假想段落，
这些内容每次略有不同 → 检索候选集变化 → 命中结果翻转。

**这对「评测平台」的立身之本是真问题**：只要默认集里有规划类特性，两次消融就不可比。
补救方向（择一）：
1. 消融时把 `plan_question` 的输出缓存/固定（同一条用例复用同一份计划）；
2. 规划类特性在评测中单独成行，与确定性基线分开报告；
3. 记录每次运行的 plan 输出，随结果一起落库，便于审计。

## 五、发现二：改写通道无增益

`rewrite_query` 把口语问句压成紧凑检索串（去疑问后缀、归一法条编号、拼实体词）作为额外一路通道。
实测在确定性配置下：
- hit@5 不变（0.75 → 0.75）
- MRR 略降（0.5104 → 0.5042）

**建议**：把 `rewrite` 从 `_DEFAULT_FEATURES` 拿下（或保留但标注"未证实"），
待评测集扩样（>50 条）后重测。理由与本项目一贯原则一致——**没有数据支撑的默认开启开关不该存在**，
这正是 `tool_call` 事故（分解/退步/HyDE 长期空转却显示"无需拆分"）给的教训。

> 注意区分：本次给 #6 带来的收益来自**结构化引用抽取 + 同义词映射**（关键词通道与过滤层），
> 与改写通道无关——两者经常被混为一谈，实证上必须分开看。

## 六、发现三：结构化引用 + 同义词确实有效

「第4页的插图是什么？」修复前后（答案级判官，同一套用例）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| #6 正确性 | 0.00 | **1.00** |
| 聚合 correctness（前 3 例） | 0.633 | **0.94** |
| 聚合 faithfulness（前 3 例） | 0.936 | **1.00** |
| 未支撑论断 | 2 | **0** |

端到端从「返回《傲慢与偏见》的插图页」变为「唯一返回 `RAG.pdf#158`」。

## 七、阻塞项：LLM 余额耗尽

跑全量答案级评测（8 例 × pipeline + agent）时中断：

```
openai.APIStatusError: Error code: 402 - {'error': {'message': 'Insufficient Balance'}}
```

因此**答案级评测目前只有前 3 例的数字**，agent 模式对照**未跑**。
顺带修掉一个健壮性缺陷：单例生成失败原先会让整轮评测崩溃，现在改为记录失败、继续跑其他用例，
并在汇总里输出失败数（`失败=N`）。
