## 四、发现一：规划通道破坏可复现性

同一条查询（#5「什么是 FastAPI？它有什么特点？」）在同一配置下：

- 首轮消融的 `default(含改写)`：**未命中**
- 手工单跑同一配置：**命中**
- 首轮消融的 `none(纯向量)`：**命中**

唯一差异是规划类特性（decompose / stepback / hyde）会调 LLM 生成子查询、退步问题、假想段落，
这些内容每次略有不同 → 检索候选集变化 → 命中结果翻转。

**这对「评测平台」的立身之本是真问题**：只要默认集里有规划类特性，两次消融就不可比。
补救方向（择一）：
1. 消融时把 `plan_question` 的输出缓存/固定（同一条用例复用同一份计划）；
2. 规划类特性在评测中单独成行，与确定性基线分开报告；
3. 记录每次运行的 plan 输出，随结果一起落库，便于审计。

## 五、发现二：改写通道的增益无法与噪声区分

`rewrite_query` 把口语问句压成紧凑检索串（去疑问后缀、归一法条编号、拼实体词）作为额外一路通道。
确定性配置下：hit@5 不变（0.75 → 0.75），MRR 略降（0.5104 → 0.5042）。

补充第三轮测量（规划生效、LLM 恢复后）后，三次独立测量的 ΔMRR 落在 **−0.006 ~ +0.135**：
详见 §8.3。由于 8 例评测集里 1 例翻转就值 0.125 hit@5，**这些差异全部落在噪声带内**。

**建议**：暂不下「移出默认集」的结论——因为**没有证据说明它有害，也没有证据说明它有用**。
正确做法是**先扩样到 ≥50 条再判**。在此之前调整默认开关都等于拍脑袋，
这正是 `tool_call` 事故（分解/退步/HyDE 长期空转却显示"无需拆分"）给的教训。

> 注意区分：#6 的收益来自**结构化引用抽取 + 同义词映射**（关键词通道与过滤层），与改写通道无关——
> 两者经常被混为一谈，实证上必须分开看。

## 八、全量结果（LLM 恢复后补跑，8 例）

### 8.1 答案级评测：Agent 明显优于管线

| 配置 | faithfulness | correctness | 未支撑论断 |
|---|---|---|---|
| pipeline(含改写) | 0.9313 | 0.6125 | 5 |
| **agent(steps=4)** | **0.9904** | **0.7313** | **1** |

逐例正确性（pipeline → agent）：

| 用例 | 类型 | pipeline | agent |
|---|---|---|---|
| #5 | FastAPI 定义 | 0.95 | 0.95 |
| #6 | 第4页插图 | 0.95 | 1.00 |
| #7 | ReCite CiteLocator 消融（多跳）| 0.50 | **0.90** |
| #8 | CAP-8 + Strict F1 | 1.00 | 0.90 |
| #9 | QueryPlanner 消融（多跳）| 0.50 | 0.40 |
| #10 | ReCite 设计思路 + 对比基线（多跳）| 0.20 | **0.40** |
| #11 | FastAPI 最小示例 | 0.80 | 0.80 |
| #12 | 两套文档网址 | 0.00 | **0.50** |

**这修正了本报告初稿（及更早口头结论）的判断。** 早前基于 n=1（#7 那道多跳题）说
「Agent 基本不值得」——本次同一道 #7，agent 0.90 vs pipeline 0.50。样本从 1 扩到 8 后，
Agent 在**正确性（+0.12）、忠实度（+0.06）、幻觉（未支撑论断 5→1）**三项全面更好。

代价仍然存在：agent 每例 4 步、多次 LLM 调用与检索，延迟与成本显著更高。
结论应表述为「**质量更好但更贵，适合复杂多步问题**」，而不是「不值」。

> 保留意见：n=8 仍偏小，且判官本身有噪声（0.1~0.2 的差异可能部分来自判官）。
> 要下强结论需要扩样并做重复测量。

### 8.2 检索消融（规划通道现在真正生效）

| 配置 | hit@5 | MRR |
|---|---|---|
| none(纯向量) | 0.625 | 0.4000 |
| default(含改写) | 0.750 | 0.5625 |
| default-改写(关) | 0.750 | 0.5417 |
| +graph | 0.750 | 0.5042 |

| all(+rerank:rrf) | 0.750 | 0.6042 |

### 8.3 改写通道：三次测量互相矛盾 → 判定为「无法与噪声区分」

| 测量 | 配置对比 | Δ MRR |
|---|---|---|
| 首轮（规划部分生效）| default vs default-改写(关) | +0.135 |
| 第二轮（确定性，无规划）| routing+keywords vs +rewrite | **−0.006** |
| 第三轮（规划生效）| default vs default-改写(关) | +0.021 |

三次 Δ 分布在 −0.006 ~ +0.135 之间，而 8 例评测集里**1 个用例翻转 = 0.125 hit@5 / 约 0.1 MRR**——
也就是说这些差异全在噪声带内。**结论：现有证据不支持「改写通道有增益」，也无法证明它有害。**

同理，规划通道的效果（0.5104 → 0.5417，Δ≈+0.03）也在噪声带内，不能据此断言有效。

**这直接指向一个方法学结论：8 条评测例分辨率不足**，任何小于 ~0.1 的差异都不可判读。
在扩样（建议 ≥50 条）之前，不应再基于单次消融调整默认开关。

### 9.0 仪器修复：vector_score 污染（复测后数字不变）

复测前发现并修复了一个测量仪器缺陷：`rrf_merge` 在行没有显式 `vector_score` 时用
`score` 兜底，而关键词通道的 `score` 是**命中词数**（≥1）、图谱通道是**跳数分**（≥1）——
它们冒充余弦进入 `_relevance_filter` 后，会让「无精确匹配即清空」的 0.45 阈值闸门
在关键词开启时永远敞开。函数注释本意是"关键词通道没有向量分，视为 0.0"，代码与注释相反。

修复：在通道入口显式打标（`_stamp_cosine` / `_stamp_non_vector`），`vector_score` 只认真
余弦；补 3 个回归测试锁死该契约（关键词行融合后必须记 0.0、噪声不得借关键词假分闯过闸门、
向量行必须携带真实余弦）。

**复测结论：§9 全部数字逐格不变。** 两轮完全一致；关键词逐例分布（25/10/28）、结构化切分
（−0.1389 / −0.1081）、留一法（#6 剔除前后 +0.110 → −0.0167）全部与修复前一致。
原因：修复后统计闸门的实际触发率——**0/63 例**出现「有候选但被清空」。这套评测集都是
可回答的问题，向量通道的最高余弦几乎总是 ≥0.45（或精确匹配档直接命中），假分从未成为
闸门的唯一依据。

这条发现的价值不在数字变化，而在两件事：
1. §9 的结论不依赖侥幸——仪器修好后结论原样成立，且「两轮一致」的可复现性检验
   在修复后的仪器上重新过了一遍；
2. **关键词门控（下一节 P0）必须读真余弦**：修复前关键词行身上的 1.0~3.0 假分会越过
   任何 ≤1.0 的分数下限，门控会形同虚设——重蹈 §9.5 的覆辙（假设合理、测量工具坏了）。

### 9.1 发现四：路由通道实测「零影响」

`routing only` 与 `none(纯向量)` 在**两个子集上都逐位相同**。原因不神秘：`_MIN_ROUTE_SCORE=0.70`
的校准结论本就是「兜底常开」（取在实测路由分最大值之上），于是路由命中的文档通道 + 全局兜底
= 全局向量检索。**即路由通道是设计上的摆设**——它不改变结果，只多花一次 doc_index 查询。

这不是 bug，但意味着「四通道混合检索」的表述需要修正：**实际起作用的是向量通道（+ 关键词通道，视问题类型）**。

### 9.2 发现五：关键词通道的收益取决于问题类型，符号会翻转

| 子集 | 关键词通道的效果 |
|---|---|
| 人工 8 条 | **有帮助**：hit@5 0.625→0.750，MRR 0.400→0.510 |
| 自动 55 条 | **有害**：hit@5 0.927→0.891，MRR 0.796→0.646 |

人工题里包含「第4页插图」「两套文档网址」「法条编号」这类**需要字面/结构化线索**的问题，关键词通道正好补向量的短板；
而自动题由模型依据单个切片生成，措辞与原文语义接近，稠密检索本已足够，关键词的子串匹配与同义词扩展
反而引入大量弱命中噪声，被 RRF 抬进了前列。

**结论：关键词通道不应无条件常开**（ΔMRR −0.117，逐例 25 变差 / 10 变好 / 28 不变）。
（仪器修复后复测：逐例分布与 Δ 完全一致，见 9.0。）

~~合理方向是「只在查询含结构化引用时启用」。~~ **该假设已被证伪，见 9.5。**

### 9.3 发现六：改写通道在 n=63 上可判定为负向

ΔMRR 由人工子集的 −0.006 变为全量的 **−0.082**（≈ 5 倍分辨率），两轮完全一致。
这次不再是「无法与噪声区分」：**在有足够样本量的前提下，改写通道拖低了排名质量**。

且它是**三个子集上全负**的唯一特性（人工 −0.006 / 自动 −0.093 / 全量 −0.082），
而它每次查询都要额外跑一路向量 + 关键词检索，属纯成本。
（9.0 仪器修复后复测：三个子集 Δ 与逐例分布完全一致，结论维持。）

**已落地改动**：`rewrite` 已移出 `_DEFAULT_FEATURES`（`src/retrieval.py`），需要时通过
`features=[..., "rewrite"]` 显式开启；`tests/test_retrieval.py` 补了默认关闭的回归断言。

### 9.4 方法学提醒：合成题集不能替代人工题集

自动生成的题是「答案就在这块切片里」的形态，天然偏向稠密检索；真实提问（如人工题）更多是
字面/结构化查找。两者结论**方向相反**，正说明需要 `origin` 区分统计——**不要只看合计数**。
本次保留 `origin` 字段的价值就在这里。



### 9.5 关键词通道的逐例归因：「结构化线索」假设被证伪

（9.0 仪器修复后复测：本节数字逐格一致。）

上一节提出「只在查询含结构化线索（页码 / 法条号 / 图表编号 / 网址 / 代号）时启用关键词」，
用 `scripts/analyze_keywords_channel.py` 在 n=63 上按该规则切分验证，结果**与假设相反**：

| 子集 | n | vector | +keywords | ΔMRR |
|---|---|---|---|---|
| 含结构化线索 | 18 | 0.944 / 0.7963 | 0.889 / 0.6574 | **−0.1389** |
| 无结构化线索 | 45 | 0.867 / 0.7256 | 0.867 / 0.6174 | −0.1081 |

（每格为 `hit@5 / MRR`。结构化线索的判定为正则启发式：页码、法条号、Table/Figure 编号、
网址、arXiv 号、连字符代号、反引号代码。）

结构化线索不仅没有预测到收益，**含有结构化线索的题反而受损更重**。反例很直接：
`#17`（Figure 2）与 `#57`（Table 3）正是最典型的图表编号类查询，却分别 ΔMRR −0.50 与
**−1.00（命中→未命中）**——字面编号匹配把其它图表/表格的切片排到了前面。

#### 留一法：人工子集的「正向」由单条撑起

人工 8 例上关键词 ΔMRR = **+0.110**，是它唯一的正面证据。逐例拆开后：

| id | ΔMRR | 命中变化 | 问题 |
|---|---|---|---|
| 5 | +0.5000 | 不变 | 什么是 FastAPI？它有什么特点？ |
| **6** | **+1.0000** | **未命中→命中** | **第4页的插图是什么？** |
| 7 | −0.6667 | 不变 | ReCite 的 CiteLocator… |
| 8 | 0 | 不变 | CAP-8 指什么？ |
| 9 | −0.2500 | 不变 | QueryPlanner 训练数据… |
| 10 | 0 | 不变 | ReCite 核心设计思路… |
| 11 | +0.3000 | 不变 | FastAPI 最小示例… |
| 12 | 0 | 不变 | FastAPI 两套文档网址… |

**剔除 #6 后，人工子集 ΔMRR = −0.0167（n=7）。**

即：所谓「关键词通道对人工题有益」是**单条用例的假象**，去掉这一条就与自动子集同号。
#6 是真实的收益（页码字面查找正是关键词该干的活），但 1 条不足以支撑常开。

#### 处置建议

- **不要按「结构化线索」做条件启用**——已证伪，且实现成本不低。
- 关键词通道**整体净负向**是事实（25 变差 vs 10 变好），但**暂不移除**，因为
  它救回的 #6 属于真实且可解释的需求，粗鲁关闭会牺牲这类查询。
- 真正的出路是**修通道质量而非开关**：关键词通道产出大量弱命中后被 RRF 抬进前列。
  → 已按此落地并重测，见 9.6。

### 9.6 门控落地：关键词通道由负转正（25 差 / 10 好 → 5 好 / 0 差）

按 9.5 的结论实现**同义词组覆盖门控**（`_gate_keyword_rows`，src/retrieval.py）：
把 `expand_terms` 的扁平词表归并为同义词组（与 `_relevance_filter` 同口径，避免同义词
扩展虚增/稀释命中数），要求关键词候选至少覆盖 **50% 概念组**；组数 ≤2 时不收紧，
保住「第4页的插图」这类单一精确串救援（它们另有 `inject_ref_channel` 兜底）。
门控只按组覆盖判定，**不读命中词数**（量纲纪律，见 §9.0）；余弦下限仍由
`_relevance_filter` 在修复后的真 `vector_score` 上执行。trace 记录 `keywords_gated` 便于观测。

重测（n=63，确定性配置，两轮逐格一致）：

| 配置 | hit@5 | MRR | ΔMRR vs 纯向量 |
|---|---|---|---|
| none(纯向量) | 0.889 | 0.7458 | — |
| keywords(门控前) | 0.873 | 0.6288 | −0.117 |
| **keywords(门控后)** | **0.921** | **0.7960** | **+0.0502** |

逐例分布与救援情况：

| 指标 | 门控前 | 门控后 |
|---|---|---|
| 变好 / 变差 / 不变 | 10 / **25** / 28 | **5 / 0** / 58 |
| 命中→未命中 | 4 例（#17 #57 等） | **0 例** |
| 未命中→命中 | 3 例 | [6, 42]（结构化救援保留） |
| 人工子集 ΔMRR | +0.110 | **+0.1875** |
| 自动子集 ΔMRR | −0.150 | **+0.0303** |

**结论**：
1. 关键词通道的损害**全部来自弱命中**——拦掉它们后通道由净负转净正，且零副作用
   （没有任何一例变差）。门控后的 keywords 等价于「纯向量 + 严格增量」，
   `#17`/`#57` 这类被字面编号拖下水的用例也恢复到纯向量水平。
2. **存废问题就此了结：保留**。门控后 keywords（0.921 / 0.796）已是全部配置里最优。
3. 新增 4 条门控测试（全量 227 条通过）；门控常数 `_KEYWORD_MIN_COVERAGE=0.5`
   换语料后应重新校准。
